# Codex 单卡片回复

用户已确认：正常长度每轮一张卡片，超长答案允许分段续发，过程只保留一份。执行过程在运行时展开，答案出现或运行结束后收起，最终答案直接展示。首次实施仅修改源码；后续用户已授权编译并更新独立测试机器人，不运行单测，不修改生产服务。

## 方案

采用 CardKit JSON 2.0 卡片实体，持续更新同一实体。过程文字、模型提供的思考摘要和工具调用进入“执行过程”面板：运行中且没有明确最终答案时展开；`finalText` 有内容或进入终态后收起，仍可手动展开查看。正常长度最终答案显示在面板外。结束、失败、中断和超时都在原卡片中收尾。正常长度且只有最终答案的轮次直接发送完成态卡片，空轮次不创建占位消息。

工具调用沿用简洁过程消息的摘要格式，仅显示工具名称、简短参数和运行状态；不将工具返回正文或完整输入拼入过程面板。读取到的 SKILL 内容、命令标准输出及工具错误正文仍保留在本地会话记录中，不随折叠展开显示。

Codex 各回复模式在开始处理时异步添加“敲键盘”表情确认，沿用既有结束清理逻辑，不等待首张卡片出现。过程文本去掉段落首尾空白，连续工具调用合并为紧凑列表；仅在段落之间保留一个空行，段落内部及最终答案的 Markdown 排版保持原样。

异常结束时没有明确的 `final_text`，既有文字继续保留在受大小限制的过程面板中，终止提示显示在面板外；不将全部历史过程推断为答案，不修改 Codex 事件翻译协议。

最终答案只在收尾时发布。按实际渲染卡片 JSON 的 UTF-8 大小计量，超过 28000 字节则分段发送答案，为平台 30KB 限制保留余量；飞书明确返回容量错误 200860/230025 时也转分段。续发使用原生富文本 `post` 的 `md` 标签，按序列化 Markdown 内容最多 8000 字节切分，覆盖没有换行的超长单行；标准反引号、波浪线代码围栏跨段时闭合并重开，不删除源文本。特别长的围栏头保留为源文本，不复制可能撑满分段的巨大围栏头。沿用邮件脱敏、原回复目标和话题参数，每段固定 UUID，不自动改发群顶层或尝试其他格式。已有过程卡片仅更新为收起的过程和简短后续消息提示；没有过程时直接发送答案分段，不创建额外提示卡。授权失败停止操作，未知发送结果不自动重发完整答案。

仅折叠原过程消息仍留下两条消息，完全删除过程则失去按需查看能力，因此均不采用。折叠只改变飞书界面，不删除卡片数据，也不改变后续上下文提取规则。

## 范围与约束

- Codex 的 `card` 和 `markdown` 回复使用单卡片；显式 `text` 模式只发送最终文本。
- Codex 不再单独发布 COT 消息；Claude 既有路径保持原行为。
- 复用 SDK、邮件脱敏和工具显示偏好，不增加依赖或配置项。Codex 折叠过程卡片不显示终止按钮；其他既有卡片的签名按钮机制保持原样。
- 更新串行执行，sequence 严格递增，过程展示受大小限制；最终答案不因过程限额被截断，超长答案分段发送。
- 原生流式模式最长 10 分钟，提前关闭后继续更新同一实体。结束时显式关闭流式模式。
- 创建或发送结果不确定时不盲目发送第二张卡。权限错误停止当前卡片后续 API 操作；其他更新失败在收尾时尝试修复原卡片。
- 首次实施时 GitHub 认证失败，已停止远端操作；本地分支基于备份提交 `98b5060`。用户后续通过官方 CLI 完成本人账号 `zbwang163` 授权；上游只有读取权限，在个人 fork 中以 `master` 保存该快照，再向它提交功能 PR，避免混入原有定制。
